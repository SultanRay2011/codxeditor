Plain-language summary

Use the workspace responsibly and keep control of your work

This summary helps explain the longer terms but does not replace them. The most important practical rules are straightforward.

Your project remains yours

You keep ownership of code and media you create. You are responsible for having permission to use anything you import, upload, publish, or commit.

Protect sensitive values

Do not put passwords, API secrets, private keys, or confidential data in client-side files, public links, collaboration chat, screenshots, or GitHub commits.

Invite people you trust

People admitted to a collaboration session may see or change shared project content according to their permissions. The host is responsible for managing access.

Publishing is public sharing

A published link is meant to be opened by others. Review every included file and remove private information before creating or updating that link.

Connected services have their own terms

GitHub, font providers, translation services, CDNs, and the browser Node runtime are separate services with their own availability and policies.

Keep your own backup

Browser storage is convenient, not a guaranteed archive. Export the current project, use ZIP All Projects for the saved-project library, or use a repository when losing work would matter.
